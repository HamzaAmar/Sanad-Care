# 2026-09-01

## Rebuilt the /[locale]/document pre-travel health questionnaire page

**Root cause of "page doesn't work":** the server action's Zod schema required
`signature`, `date` and consent, but the form never rendered those inputs — so
`safeParse` always failed and submission was impossible. The consent section,
signature and date fields simply did not exist in the UI.

### Structure now in `src/app/_components/pages/document/`

- `document.type.ts` — shared types (`DocumentValues`, `DocumentFormState`,
  `MessageLabels`, `DocumentErrorCode`).
- `document.utils.ts` — **pure** module (no "use client"/"use server") with
  `readDocumentFormData`, `buildDocumentMessage`, `buildWhatsAppUrl`,
  `emptyDocumentValues`, `countCompletedSteps`/`countTotalSteps`. Imported by
  BOTH the client (live preview + progress) and the server action, so the
  previewed message is identical to the sent one.
- `action/document.ts` — validates, returns **error codes** (not sentences) +
  `fieldErrors` + `unansweredQuestions[]`. Never throws.
- `form.tsx`, `index.tsx`, `components/question-card.tsx`,
  `components/success-panel.tsx`, `_main.scss`.

### Conventions established (reuse these)

- Validation errors travel as **codes** (`required`, `tooShort`, …) and are
  translated client-side via `t("errors.<code>")`. Avoids server-side i18n in
  server actions; keys live under `document.errors.*` in messages/*.json.
- Server action returns `values` on success; the **client** builds the WhatsApp
  URL from validated values using its own translations.
- Guard submit side-effects with `handledRef.current === state.submittedAt`
  (action stamps `submittedAt: Date.now()`) so a `useEffect` runs exactly once
  per submission.
- WhatsApp number now comes from `PERSONAL_INFO.contact.whatsapp`
  (+212 704 524 625), replacing a hardcoded +212 630 371 320.
- Question #10 ("I understand and agree to the terms below.") was removed from
  `document.questions` in all 3 locales and became the `consentAgree` checkbox
  label — it was a consent statement, not a health question, and duplicated the
  new consent box.

### Gotchas hit

- Deliberately did **NOT** persist the form draft to localStorage: it is health
  data and would linger on shared devices.
- Today's date is filled in a `useEffect`, not during render — rendering it on
  the server causes hydration mismatches across timezones. Use a local-time
  `YYYY-MM-DD` helper (`toDateInputValue`), not `toISOString().slice(0,10)`.
- Starting a new form after success must reset `values`/`showPreview` state and
  re-run the defaults effect (keyed on `dismissedAt`), because the `<form>`
  remounts but the component state does not.
- `oxfmt --write src` / `yarn format` is safe here; it left the user's other
  files untouched.

## UX change: submit now opens WhatsApp directly (no extra "send" step)

User feedback: the old flow showed a success panel after submit and required a
second click on "Open WhatsApp" — visitors didn't realise they had to send.

**New flow (this session):**
- `handleSubmit` (form `onSubmit`, runs inside the click gesture) validates
  client-side via the shared `validateDocument`, then `window.open`s the WhatsApp
  URL **immediately** (inside the user gesture, so popup blockers normally allow
  it).
- Server action still runs for the authoritative check + form reset. On success
  the effect resets the form to a fresh state and scrolls to top ("same page").
- Feedback banners (`doc-send-banner`): green "WhatsApp opened — tap send"
  (auto-dismiss 12s) when the popup opened; persistent amber fallback with a
  manual **Open WhatsApp** link + **Copy link** button when the popup was blocked.
- Added `document.validation.ts` (shared Zod schema + `validateDocument`) used by
  BOTH the client gate and the server action — single source of truth.
- `questions` array is now resolved on the server (`getTranslations` in the route)
  and passed as a prop, removing any client `t.raw("questions")` reliance.
- `noValidate` on the form so our localized error messages (not native bubbles)
  are the ones shown.
- Removed the now-unused `components/success-panel.tsx`.

**Verified:** `tsc --noEmit` 0 errors, `oxlint` 0 warnings, en/fr/ar all HTTP 200
with 9 questions + signature + date + consent. Dev server (pre-existing, was on
3100) served stale messages until restarted — restart to see new copy.

## Removed signature + date fields from document form (follow-up)

User asked to drop the signature & date fields at the bottom (consent section),
fix the progress math, and keep field values persisted on validation error.

- Removed `signature`/`date` from `document.type.ts` (`DocumentValues`,
  `DocumentFieldName`, `MessageLabels`), `document.utils.ts` (reads, empties,
  `countCompletedSteps` filledText, and `TEXT_FIELD_COUNT` 7→5), and
  `document.validation.ts` (schema entries).
- In `form.tsx`: dropped the `doc-consent__fields` Grid (signature + date
  `FormController`s), the `Signature` icon import, the `date`-default effect line,
  and the `signature`/`date` label entries. (arrivalDate `type="date"` stays.)
- **Error persistence:** the server action echoes `values` back on the error
  branch; the form's submission `useEffect` re-syncs `values` AND writes them onto
  the actual controls via `writeDocumentFormData()` on error (instead of
  resetting), so the live preview/progress and every typed input survive a
  validation error even if the action resets the uncontrolled inputs.
- Removed dead `signature`/`date` keys from messages/en|fr|ar.json.
- SCSS bonus: a thin divider now separates the consent points list from the
  agreement checkbox (`.doc-consent__list` border-block-end).

**Verified:** `tsc --noEmit` 0 errors, `oxlint` 0 warnings, JSON valid.
