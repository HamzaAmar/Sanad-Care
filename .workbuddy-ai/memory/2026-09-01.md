# 2026-09-01

## Rebuilt the /[locale]/document pre-travel health questionnaire page

**Root cause of "page doesn't work":** the server action's Zod schema required
`signature`, `date` and consent, but the form never rendered those inputs — so
`safeParse` always failed and submission was impossible. The consent section,
signature and date fields simply did not exist in the UI.

### Structure now in `src/app/_components/pages/document/`

- `document.type.ts` — shared types (`DocumentValues`, `DocumentFormState`,
  `MessageLabels`, `DocumentErrorCode`).
- `document.utils.ts` — **pure** module (no "use client"/"use server") with
  `readDocumentFormData`, `buildDocumentMessage`, `buildWhatsAppUrl`,
  `emptyDocumentValues`, `countCompletedSteps`/`countTotalSteps`. Imported by
  BOTH the client (live preview + progress) and the server action, so the
  previewed message is identical to the sent one.
- `action/document.ts` — validates, returns **error codes** (not sentences) +
  `fieldErrors` + `unansweredQuestions[]`. Never throws.
- `form.tsx`, `index.tsx`, `components/question-card.tsx`,
  `components/success-panel.tsx`, `_main.scss`.

### Conventions established (reuse these)

- Validation errors travel as **codes** (`required`, `tooShort`, …) and are
  translated client-side via `t("errors.<code>")`. Avoids server-side i18n in
  server actions; keys live under `document.errors.*` in messages/*.json.
- Server action returns `values` on success; the **client** builds the WhatsApp
  URL from validated values using its own translations.
- Guard submit side-effects with `handledRef.current === state.submittedAt`
  (action stamps `submittedAt: Date.now()`) so a `useEffect` runs exactly once
  per submission.
- WhatsApp number now comes from `PERSONAL_INFO.contact.whatsapp`
  (+212 704 524 625), replacing a hardcoded +212 630 371 320.
- Question #10 ("I understand and agree to the terms below.") was removed from
  `document.questions` in all 3 locales and became the `consentAgree` checkbox
  label — it was a consent statement, not a health question, and duplicated the
  new consent box.

### Gotchas hit

- Deliberately did **NOT** persist the form draft to localStorage: it is health
  data and would linger on shared devices.
- Today's date is filled in a `useEffect`, not during render — rendering it on
  the server causes hydration mismatches across timezones. Use a local-time
  `YYYY-MM-DD` helper (`toDateInputValue`), not `toISOString().slice(0,10)`.
- Starting a new form after success must reset `values`/`showPreview` state and
  re-run the defaults effect (keyed on `dismissedAt`), because the `<form>`
  remounts but the component state does not.
- `oxfmt --write src` / `yarn format` is safe here; it left the user's other
  files untouched.
